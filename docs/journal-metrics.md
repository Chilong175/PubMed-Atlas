# 期刊指标匹配与导入

## 为什么会缺失

原有表只覆盖少量常见期刊，数值仅用于 Demo；原解析器未保存 ISSN 和标准缩写，导致完整期刊名称不同于表内名称时还可能漏配。本次不新增未经核验的 IF，改为补齐匹配字段与数据导入。

匹配顺序为 ISSN（含电子版和 Linking ISSN）、标准化名称、PubMed 标准缩写。名称只规范大小写、标点和空白，不做模糊相似匹配。发现标识冲突时不匹配，避免误配。历史 SQLite 记录缺少新增字段时默认空值，需要重新获取文献才能补齐。

## 数据导入

首页“期刊指标与数据导入”支持下载 CSV 空模板。CSV 必须使用 UTF-8 编码，可带 BOM，最多 2 MB、20000 行。

| 字段 | 要求 |
| --- | --- |
| journal_name | 必填，期刊名称 |
| journal_alias | 可选，多个缩写/别名用英文分号分隔 |
| issn、eissn | 可选，须通过 ISSN 格式及校验位检查 |
| impact_factor | 必填，有限且非负的数值，0 是有效值 |
| quartile | 可选，仅接受 Q1–Q4；中科院分区不能直接填入此列 |
| source_year | 必填，整张表须为同一指标年份 |
| source | 必填，真实来源信息；填写来源不代表系统已核验真实性或使用权限 |
| quartile_system | 有分区时必填，注明体系和类别，例如 JCR / Oncology |

同一期刊若在多个学科类别有不同分区，请先明确使用的类别，每张表每个期刊只保留一行。重复名称、别名或 ISSN 会被拒绝，避免隐式覆盖。

全部记录验证通过后，原子替换 `data/journal_metrics_imported.csv`；校验失败保留旧表。导入后只使用新表，不与原 Demo 表合并。Docker 的现有 data 挂载会持久保存导入表；此文件被 Git 忽略，不提交用户数据。

页面同步显示当前表类型、指标年份、IF 匹配覆盖率、缺失期刊清单和每篇文献的来源。导入后只重新分析当前文献，不重新请求 PubMed 或 AI。界面用“暂无指标数据/暂无分区数据”，后端保留 null/Unknown 兼容已有接口。

## 边界

- 本次没有购买、抓取或提供完整 JCR 指标库。覆盖率实际提升取决于导入表质量与覆盖范围。
- 排序针对本次返回文献中可匹配指标的记录，不代表全部 PubMed 命中的前 100。期刊 IF 也不是单篇论文影响力。
- 数据导入接口沿用本地 Demo 的无登录模式；当前用途为本地可信环境。

## 接口与验证

- `GET /api/metrics`：当前表状态。
- `GET /api/metrics/template`：下载空模板。
- `POST /api/metrics/import`：JSON 中的 `csv_text` 字段。
- `POST /api/analyze`：新增 `metric_coverage`、匹配方式、指标来源；文献标识在检索、分析和 SQLite 中传递。

自动化测试使用合成 IF 数据与临时目录，验证 ISSN 优先、缩写恢复匹配、冲突拒配、覆盖率、原子导入和 SQLite 字段迁移，不将测试指标写入实际数据表。
